# Dual source orientation ownership — v0.1b8

One session state holds entry matrix/quaternion/forward/time, target SurfaceFrame, and current interpolated basis. The first exact qualifying source entry establishes it; both paths sample that SAME transition using monotonic session time. Delay>=.70 s, rotation~.25 s. Each incoming source keeps its own Position. There is no second interpolation or re-entry per frame/caller.

Common path remains exact0x2CFC580 / return0x2CFC8F3 with source=originalEntryRSP+0x28. No per-update write limit exists: every valid matching invocation, including multiple calls in one native update, is supplied the current basis. b8 removes two artificial coverage failures: worker elapsed may trail a fresh native token, and sampled orientation loss previously aborted ownership and blocked subsequent valid calls. Native elapsed is authoritative in dual mode; worker identity/freshness is still mandatory. Reset observations now invalidate retention but do not stop exact valid source ownership. Invalid source, owner, normal, lifecycle, patch, stack, SDK identity, log capacity or kill gates still fail closed.

Second path is independently authenticated0x2CFC3C0 / return0x2CFC84B. See RESET_COPY_WRITER_ANALYSIS.md. Entry source basis/Position and raw args are its own data, not a prior common entry. `COMMON_SOURCE_OVERRIDE`, `LATE_COMMON_WORLDUP_OVERRIDE=1`, `RESET_COPY_SOURCE_ENTRY` and `RESET_COPY_SOURCE_OVERRIDE` distinguish the paths. The late marker identifies repeated same-update WorldUp inputs; it does not invent which old admission gate failed in the private b7 log.

After interpolation completion, fresh matching native PRE observations accumulate retained ActorUp dotN>=.98 for300 ms OR20 distinct native updates. Duplicate same-update calls cannot inflate this metric; a bad same-update native/worker observation still breaks continuity; a missing>100 ms observation gap or lost/invalid basis resets the continuous interval. Both source paths must have committed before dual-mode retention can pass. `ORIENTATION_RETENTION_PASS=1` is a historical observed interval, not a promise that later writes never reset it. Worker samples alone cannot pass. Bounded maximum4096 source writes /5 s; budget exhaustion is explicit, not permission to write longer or directly to Actor.

The primary-thread hardware watch is retained from~.60 to1.50 s in dual verification mode, or until reset/Deinit/identity/guard loss/F8/budget. b7 standalone diagnostics retain their1.10 s deadline. Quiet writes with unchanged Up no longer consume event/log budget in dual mode. Still bounded256 changed events,8 windows,1024 common/status records; overflow/contention stops capture with a drop. No additional thread enumeration is introduced. A candidate after commits from BOTH paths logs NEW_RESET_AFTER_DUAL_OVERRIDE. Sequential dword resets can end with a non-surface intermediate old row: a <=5 ms prior observed surface anchor is logged separately as RESET_SEQUENCE_CANDIDATE, with explicit non-atomic semantics. Hardware RIP is post-store and actual effective address/function hash still needs private anchored decoding. No-event/primary-only coverage does not prove absence of other writers.

Offline `tools/review_dual_source.py` checks accepted header/hash, exact original copy hash/admission, own-entry layout/stack/caller/target/Position evidence, distinct mapped A/E sessions, retention marker, new-reset events and later sampled retention loss. Synthetic logs never establish game ownership. It grants no adhesion/direct Actor permission.
