## Why a separate bounded predicate is justified

Current accepted official Intel SDM Vol3B253669-090US/February2026/20.2.3 defines
DR6 as last-event status and Dr0-Dr3/Dr7 as breakpoint address/control. BLD11 is
active-low for bus-lock-detection DB; other DBs do not modify it and handlers
should leave/set11. RTM16 is active-low for advanced RTM debug, other DBs set it
and handlers should leave/set16. These fields do not enable/address/type/length
a watch. The existing production ownership uses Dr0/Dr1 addresses and Dr7 fields,
claims B0/B1, and does not use11/16 for slot or lease ownership.

Current Microsoft GetThreadContext source requires suspension/ContextFlags.
SetThreadContext documents possible silent correction of non-specifiable,
OS-controlled debug state; it does NOT grant blanket DR6 equivalence. Retrieved
current MicrosoftDocs sources remain4479/4383 bytes, SHA256 respectively
82be7f41ca82e777e3a731bb9cb5169816bf86d4e6a4fd2bc70b48e3842b9597 and
af689d9e657208757e6d1c8b74e7b757c711122c321fe6a3a5a6191619fd1618.
Exact URLs/status/hashes are in V01C47_STATUS.json. Current Intel delivery still
returns proxy403, so PDF bytes/hash are unavailable; the accepted owner current
primary extraction remains the best reference and is not downgraded to old
mirrors or called a PDF hash. No raw vendor PDF/game log is redistributed.

Crucially, native c46 already has11/16=1 before any target access or owned DB.
The difference is therefore not an enabled owned watch nor a cause requiring
