## Stage-3 route (plan)
1. Jump vector: WS jump should leave along the wall normal (WS "up") and keep the travel velocity along the wall.
   Cheapest route is the WR jump config (owner-extracted, decoded above). M8b tests one field group.
2. Charge jump: hold detection during WS + a stronger jump-off. If M8b shows the config controls the jump-off vector,
   a charge jump can scale those values for one jump (in-memory config value write, bounded/restored) instead of a
   new velocity writer. Otherwise a hero velocity route is required (none proven yet).
3. Gravity-keeping: earlier static research found game functions GravityOrientationOwner (RVA 0x134EF00) and
   SetGravityVector (RVA 0x35132A0, no .pdata, 19 instructions; Scripted Flight reference calls it with RCX=object,
   RDX=3-float vector; static chain RCX=load64(load64(owner+0xF0)+0xF8)+0x5F4). c45: the owner entry was not executed
   during ordinary locomotion/WR. Object source, frame, units and lifetime are UNKNOWN (analysis/MOTION_GRAVITY_*).
   This is the candidate route for gravity toward the wall during the WS jump; needs its own bounded experiment.
4. Orientation in the air: keep the WS orientation during the jump and return to upright when gravity returns
   (depends on 3; the orientation override is currently gated on the native WR lifecycle).
