# v0.1b7 prearmed reset trace

Native lifecycle Update triggers a bounded request at elapsed >=0.600 and <1.100 s. A matching current-Hero common-writer entry is an independent fallback; neither waits for worker polling to see tilted Up. Worker-published session/Hero identity must be <=100 ms old, and exact-build/owned lifecycle/common-writer/caller guards remain required. A helper validates fresh lifecycle/generation/owner/Hero identity and arms the known primary native thread only. No Toolhelp enumeration precedes or follows the primary in this version. After SetThreadContext the helper reads back both owned slots before reporting installation. Primary DR0 watches Transform+0x10..17 (8 bytes), DR1 +0x18..1b (4 bytes), write-only. Occupied debugger slots are refused; native code is never suspended while the helper holds a callback lock or calls SDK/log allocation.

Capture deadline is native Init+1.100 s, not commit+30 ms. Source override still starts >=0.700 s through the original .25 s interpolation and all original guards. No override is delayed for diagnostics. Initial basis sanity is checked on admission; ongoing identity checks intentionally do not reject a transient partially written basis between native stores. A helper scheduling delay can miss the first commit: PREARM_STATUS first_override=1 reports actual installation-before-commit evidence, not a promise. PREARM_STATUS=0 or no status is not a useful successful session.

At each source commit, save QPC separately from the prearm request; hardware events snapshot the last committed QPC at event time, never a future commit while draining. Before the first commit, relative timing is unknown. A surface-like -> WorldUp candidate requires normalized before dot N>=.50, after dot WorldUp>=.98 and, in b7, a source commit. Native Deinit/owner faults synchronously invalidate capture; helper performs physical DR cleanup. Handler also checks killed/capture/deadline/event budgets. OS scheduling can delay restoration, and non-primary/new threads are intentionally uncovered.

No new native target, unknown typed game ABI, direct Actor/Position/reset patch, adhesion/movement/camera/physics/animation changes. Budgets: 8 sessions/process, 256 hardware events/window, 1024 buffered common/status records and 512 buffered hardware events. Contention/overflow stops the capture with dropped evidence. Owned immutable VEH tombstones remain resident to clear delayed owned exceptions without consuming unrelated debugger slots.

Old Up is a previous observation, not an atomic pre-instruction value. Hardware RIP is post-store. Multi-store/concurrent writes can hide transitions. Runtime candidates are not verified instructions. Complete bounded private function capture + AMD64 boundary + SHA256 + anchored Capstone effective-address decode are required offline; private game bytes never enter release ZIPs.
