Actual protocol:

1. WS authenticates B0 while foreign B2 remains, calls the original handler,
   observes SEARCH, captures c50 identity and reserves immutable pending1 BEFORE
   SEARCH escape. The counter/identity are independent of the diagnostic ring.
2. A separate foreign owner authenticates the same context, clears only its B2
   and returns EXECUTION. No earlier RIP redirection skips that owner.
3. Real VCH must observe exact downstream-final CONTEXT/thread/exception/order
   with c50 unique worker identity. It snapshots the final state and signals a
   manual-reset arrival event, then uses the original bounded2000ms owned hold.
4. Only after real VCH arrival does the coordinator request close. Pending1
   prevents legacy final polling. Outside VCH it prepares and verifies the old
   c41 stub for that exact RIP, binds every identity field and publishes it with
   release ordering. Unknown/cap/preparation/publication failure keeps poison/debt.
5. VCH acquires publication, rechecks final CONTEXT, complete immutable identity,
   ticket metadata/code address, current code/pages/target and marker0. It changes
   ONLY saved Rip, captures exact byte differences and publishes redirection.
   Any byte outside Rip fails; unknown extra byte offsets are reported. VCH does
   no executable allocation, Capstone call, formatting, ring lock or discovery.
6. OS must actually execute the reviewed marker-store/direct-jump continuation.
   Only its exact observed token, current code and all9 identity fields can
   acknowledge that debt. The coordinator's sequential ledger mirrors actual
   callback publications; it does not synthesize callback dispatch or token writes.
7. Exact acknowledgment permits pending0 and the original final poll. Obtain
   saved/pre-poll/after/three real suspended-worker DR readbacks and lease/poll
   state BEFORE judging success. A second watched access is never requested.
8. Keep RX/marker memory alive and unreused even after acknowledgment/cleanup.
   Verify machine state and one actual hit. Release the harness, join the retained
   real worker (and optional idle worker), THEN free storage and deregister the
   test-owned downstream/VCH callbacks. EXE code remains resident through exit.

The helper-unit allocation is never published to a worker and is freed locally;
that is not live continuation reclamation. In the real protocol, marker
acknowledgment never sets STUB_EXECUTION_QUIESCENT/STORAGE_RECLAIMABLE. Only the
signaled retained worker handle permits terminal storage free. This is not an
all-production registration/credit/lifetime or live-slot-reuse design.
